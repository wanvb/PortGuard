# PortGuard Web 控制面板规格

> 面板是程序唯一的图形界面（原 Win32 GUI 方案已废弃）。
> 前后端同处一个 exe：静态资源经 `include_str!` 内嵌，运行时不读取磁盘。

---

## 1. 形态与访问

| 项目 | 说明 |
| --- | --- |
| 默认地址 | `http://127.0.0.1:18080` |
| 默认绑定 | `127.0.0.1`（仅回环） |
| 端口占用 | 启动时自动向后顺延，最多尝试 10 个端口，并在日志中告警 |
| 认证 | **无口令**，安全性由「只监听回环 + 请求头校验」保证 |
| 浏览器要求 | 现代浏览器（ES6、fetch、CSS Grid，不兼容 IE） |
| 打开方式 | 托盘右键「打开控制面板」、`--open-panel`、启动时按配置自动打开 |

### 1.1 安全边界

无口令意味着**任何能访问该端口的人都能封停 IP**，因此设置了三道闸：

1. **只监听回环**：默认绑定 `127.0.0.1`，外部主机无法连接。
2. **Host 头校验**：Host 必须是实际监听地址、`127.0.0.1:<port>`、`localhost:<port>` 或 `[::1]:<port>` 之一。用于阻断 DNS rebinding（攻击者把域名解析到 127.0.0.1 诱导浏览器提交变更）。校验使用**实际监听地址**而非配置里的绑定串，否则端口顺延后所有请求都会被误判为伪造。
3. **Origin 头校验**：跨站来源的变更请求一律拒绝，防 CSRF。

补充限制：

- 请求体上限 1 MiB
- 变更接口只接受 JSON 请求体，不接受查询串传参（避免 URL 被误触发或留在浏览器历史里）
- 所有写操作都记入日志

## 2. 页面结构

单页应用，左侧导航 + 顶部状态条，五个页面互斥切换：

```text
┌────────────┬──────────────────────────────────────────┐
│ PortGuard  │  状态 · 网卡 · 本机 IP · 权限 · 运行时长  │
│            │  [开始保护] [停止保护] [立即刷新]         │
│  概览      ├──────────────────────────────────────────┤
│  当前连接  │                                          │
│  封停列表  │              当前页面内容                 │
│  设置      │                                          │
│  运行日志  │                                          │
│            │                                          │
│  版本号    │                                          │
└────────────┴──────────────────────────────────────────┘
```

导航项带计数徽标：当前连接数、封停数。

### 2.1 概览

- 四个统计卡：跟踪中 IP、已封停 IP（副标：其中永久 N）、受保护端口、累计抓包（副标：累计封停 N 次）
  - 「受保护端口」卡片的副标必须直接列出三组端口（如 `TCP 3389 · WEB 80,443 · UDP 3389`），不能只给一个总数；三组全空时显示「三组均未设置，不会统计与封停」
- **判定明细**卡片：五项忽略计数（非本机流量、本机外连、非新建连接、端口未保护、ICMP），各带一句成因说明，数据来自 `status.stats.ignored`；下方一行脚注给出解析失败计数与样本（`status.parse_errors` / `status.parse_samples`），并在 `count_accept` 打开时说明当前按 SYN+ACK 统计
- **抓包观测**表格：列「方向 / 协议 / 本机端口 / 标志 / 包数」，数据来自 `status.observed`（按次数降序取前 12 条）。这张表回答「这个端口的包到底有没有被收到」，没有数据时给出「保护未启动 / 还没抓到任何包」的空态说明
- **最近事件**列表：封停、解封与系统提示
- **系统防护开关**：危险端口保护 / 禁止 Ping / 开机自启 / RDP 客户端保护，直接调 `/api/protection`

### 2.2 当前连接

表格列：IP、地理位置、协议、服务端口、分组、窗口内次数、累计次数、最近时间。

- 顶部搜索框按 IP / 地理位置 / 端口过滤（前端过滤）
- 地理位置列来自 `ConnectionView.location`，只用于展示（规范 22），查询不到显示「未知」
- 数据来自 `/api/connections`，只保留最近 5 分钟内活跃的记录，按窗口次数降序
- 封停成功的 IP **不会被移出列表**，其状态显示为 `BANNED`（永久为 `PERMANENT`），便于看清封停前它在打哪个端口；行仍按 5 分钟 TTL 自然消失

### 2.3 封停列表

表格列：IP、地理位置、原因、协议/端口、次数、类型（永久/临时）、剩余时间、操作（解封）。

- 顶部手动封停输入框 + 永久/临时选择 + 封停按钮
- 每条记录对应一条 `PortGuard-Ban-<ip>` 防火墙规则

### 2.4 设置

分区：监听网卡与面板地址、受保护端口与阈值（TCP/WEB/UDP 三组）、连接事件来源、封停策略、IP 名单（白名单/黑名单）、RDP 客户端保护、系统与日志、地理位置、数据目录。

- **地理位置**卡片：开关 + 数据库文件名（默认 `ip2region_v4.xdb`，相对路径依次查找 `data/`、程序目录、当前目录），下方显示当前库状态（已加载路径 / 未找到应放位置 / 加载失败原因）
- **连接事件来源**卡片：一个开关「统计服务端应答（SYN+ACK）」，对应 `protect.count_accept`；说明文字必须点明「部分云主机 / 网卡的混杂模式收不到入站包」，并指向概览页的「抓包观测」用于确认

- 保存时整体提交 `POST /api/config`
- 校验失败的字段以中文错误列表显示在页面顶部，**失败时不清空用户已填内容**
- 三组保护端口全空时服务端返回 400（文案含「保护端口为空」），前端按普通校验错误展示
- 名单规则格式提示：`192.168.1.1`、`192.168.1.1-192.168.1.100`、`192.168.1.*`

### 2.5 运行日志

滚动显示 `/api/logs` 返回的日志行，级别着色。

## 3. 接口契约

统一约定：

- 只读接口 `GET`，返回 JSON；变更接口 `POST`，请求体为 JSON
- 错误一律返回 `{"error":"中文说明"}`，前端直接展示该句子
- 参数错误返回 400，服务端问题（防火墙失败、权限不足）返回 500
- 成功返回 `{"ok":true}` 或返回受影响对象（如保存配置返回规范化后的 `Config`）

### 3.1 只读接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/` | 面板首页（内嵌 HTML） |
| GET | `/assets/<name>` | 内嵌 CSS / JS |
| GET | `/api/state` | **聚合接口**：`{status, connections, bans, events(80)}`，一次拉取全部 |
| GET | `/api/status` | 运行状态与统计 |
| GET | `/api/connections` | 当前连接列表 |
| GET | `/api/bans` | 封停列表 |
| GET | `/api/config` | 当前配置 |
| GET | `/api/adapters` | 可用网卡列表 |
| GET | `/api/logs?limit=N` | 日志（默认 300，上限 5000） |
| GET | `/api/events?limit=N` | 事件（默认 100，上限 1000） |
| GET | `/api/meta` | 版本、日志路径、数据目录、启动时间 |

`/api/status` 响应字段：

```json
{
  "running": true, "adapter": "192.168.1.8", "local_ip": "192.168.1.8",
  "panel_bind": "127.0.0.1:18080", "admin": true, "capture_ready": true,
  "stats": {"tracking": 0, "banned": 1, "permanent": 1,
            "captured_packets": 1262, "total_bans": 0, "uptime_seconds": 4,
            "ignored": {"not_local": 0, "outbound": 0, "not_new_connection": 0,
                        "port_not_protected": 0, "icmp": 0}},
  "started_at_ms": 1791951164584, "version": "0.1.0",
  "protected_ports": 4, "risky_ports": false, "block_icmp": false,
  "autostart": false, "rdp_enabled": false,
  "parse_errors": 0, "parse_samples": [], "count_accept": false,
  "observed": [{"direction":"入站","protocol":"TCP","port":3389,"flags":"SYN","count":9}]
}
```

`observed` 中的端口是**本机侧端口**（入站取目的端口、出站取源端口），`flags` 取 `SYN` / `SYN+ACK` / `RST` / `FIN` / `ACK` / `其它`。

### 3.2 变更接口

| 路径 | 请求体 | 说明 |
| --- | --- | --- |
| `/api/start` | 无 | 开始保护（选定网卡后启动抓包） |
| `/api/stop` | 无 | 停止保护（保留封停规则） |
| `/api/ban` | `{"ip":"1.2.3.4","permanent":true}` | 手动封停；默认永久 |
| `/api/unban` | `{"ip":"1.2.3.4"}` | 手动解封 |
| `/api/lists/add` | `{"kind":"whitelist","rule":"192.168.1.*"}` | 加名单；加白会立即解封该地址 |
| `/api/lists/remove` | `{"kind":"blacklist","rule":"1.2.3.4"}` | 删名单（幂等） |
| `/api/adapter` | `{"ip":"192.168.1.8"}` | 切换监听网卡（会重启抓包并清空跟踪状态） |
| `/api/protection` | `{"key":"risky_ports","enabled":true}` | 开关：`risky_ports` / `block_icmp` / `autostart` / `rdp_guard` |
| `/api/config` | 完整 `Config` JSON | 保存配置；返回规范化后的配置 |

### 3.3 白名单的硬约束

`POST /api/ban` 在目标 IP 命中白名单时返回 400，错误信息为「`<ip>` 在白名单中，拒绝封停」。该拒绝发生在**控制器同步路径**上，不进入封停队列，因此不会产生防火墙规则。

## 4. 前端实现约束

- 纯 ES6 + `fetch`，无构建步骤、无第三方库（单 exe 内嵌，必须零依赖）
- **所有动态数据必须经 `textContent` 写入 DOM**，禁止 `innerHTML` 拼接用户可控内容（IP、日志、错误信息都可能被构造）
- 轮询间隔 1 秒，使用 `/api/state` 聚合接口，避免多请求互相错位
- 轮询失败时保留上一次数据并显示「连接已断开」，不清空表格
- 所有时间以本地时区展示；剩余时间对永久封停显示「永久」
- 深色工业风，配色以 `#111823` 为底、`#38BDF8` 为强调色（与托盘图标同源）

---

## 5. HTTP 服务实现要点

- 基于 `tiny_http`，每个连接一个工作线程，`stop` 通过标志位 + `unblock` 唤醒
- 响应头统一补充安全相关项，构造失败时跳过该头（不使用 `unwrap`）
- 静态资源按路径查表返回 `&'static str` 与 MIME，未命中返回 404
- 非 ASCII 请求路径会被 `tiny_http` 直接拒绝（返回 400），这是底层行为，非缺陷
