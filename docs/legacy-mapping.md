# 旧版迁移映射

> 记录旧版（易语言）PortGuard 与 Rust 版的对应关系。
> **决策：本项目彻底抛弃旧版数据文件，不提供任何迁移功能。**

---

## 1. 迁移状态总览

| 迁移对象 | 状态 |
| --- | --- |
| 行为语义（判定顺序、封停逻辑、端口分组） | 已迁移（依据规范文本重建，非逆向源码） |
| 配置数据（`config.dat`） | **已放弃** —— 不再读取、不再解析、不做迁移 |
| 封停数据（`BanData.bin`） | **已放弃** —— 同上 |
| 旧版源码（`PortGuard.txt`） | **已放弃** —— 仅作为行为参考文本，不作为兼容目标 |
| IP 地理位置库（`ip2region_v4.xdb`） | 已实现（`portguard-geo`，只用于展示） |
| 界面形态 | 已变更（Win32 GUI → 内嵌 Web 面板） |

---

## 2. 抛弃旧版数据文件的理由

`config.dat`、`BanData.bin`、`PortGuard.txt` 三者按用户决策**永久放弃**：

- **无格式样本**：仓库内从未提供这三个文件，盲写解析器等于凭空发明一种二进制格式，
  正确率不可保证。一个只能解析猜测格式的导入器比没有该功能更糟——
  用户会以为迁移成功，实际规则全部丢失。
- **无迁移价值**：Rust 版的 `config.toml` 是带注释的纯文本，字段语义与旧版定长结构体
  并非一一对应（如旧版无「三组端口各自阈值」「虚拟网卡开关」等概念），
  强行映射只会产生一批含义模糊的规则。
- **维护成本**：为一个一次性的、无样本的格式长期保留解析分支，违背
  「简洁实现、避免冗余代码」的项目约束。

因此：**不实现导入器，不保留兼容分支，不在配置中留旧版字段**。
用户若从旧版升级，需在新版面板中重新填写白名单 / 黑名单 / 端口阈值。

## 3. 文件对应关系

| 旧版 | 新版 | 说明 |
| --- | --- | --- |
| `config.dat` | `config.toml` | 二进制 → 纯文本 TOML，可手工编辑、可版本管理 |
| `BanData.bin` | `state/bans.json` | 二进制 → JSON，含 `version` 字段便于后续迁移 |
| `Record.log` | `logs/portguard.log` | 超过 16 MiB 滚动为 `.1` |
| `ip2region_v4.xdb` | `data/ip2region_v4.xdb` | **沿用同一文件格式**（xdb v3），随程序分发 |
| 程序目录 | 相对 exe 目录（`AppPaths::resolve`） | 绿色部署，取不到 exe 时回退当前工作目录 |
| 注册表自启项 | 计划任务 `PortGuard` | 以 `--service` 参数在开机时启动 |

---

## 4. 行为对应关系

| 旧版行为 | 新版实现 | 差异 |
| --- | --- | --- |
| 原始套接字抓包 | `portguard-packet::capture` | 无（保持同一调用顺序） |
| 判定顺序 | `portguard-core::engine` | 无 |
| 危险端口保护（135/137/138/139/445） | `PortGuard-Protect-RiskyPorts-TCP/UDP` 规则 | 无 |
| ICMP Ping 屏蔽 | `PortGuard-Block-ICMPv4/v6` 规则 | 新增 IPv6 规则 |
| 默认排除 VMware 网卡 | `network.include_virtual` 配置项 | **有意差异**：交给用户决定 |
| 无网卡自动选择 | 物理优先 + 非 APIPA 优先 | **新增** |
| 流出方向统计 | `count_outbound`，默认关闭 | **明确化**：默认只统计入站，避免误伤本机外连 |
| IP 地理位置 | `portguard-geo`（`ip2region_v4.xdb`） | 无（同一数据源） |
| Win32 窗口 + Tab + ListView | 内嵌 Web 面板 | **形态变更**（用户决策） |
| 单实例激活已有窗口 | 单实例打开已有实例的面板 | 无窗口形态下的等价实现 |

## 5. IP 地理位置库（唯一保留的旧版文件）

`ip2region_v4.xdb` 与旧版**同格式**（xdb v3），因此无需迁移，直接复用：

- 解析与查询由 `crates/portguard-geo` 实现，格式细节见该 crate 的 `CLAUDE.md`
- 库文件随程序分发，不内嵌进 exe（约 10 MiB，不适合 `include_str!`）
- 查找顺序：`data/<文件名>` → 程序所在目录 → 当前工作目录
- 配置项 `[geo] enabled` / `[geo] db` 控制开关与文件名，保存后立即生效
- **只用于展示，绝不参与封停判定（规范 22）**：查询失败、库缺失、IP 非法一律显示「未知」，
  判定路径完全不接触该模块
- 该二进制文件不入库（见 `.gitignore`），分发时需与 exe 一并提供

---

## 6. 不应做的事

- 不要凭猜测编写 `config.dat` / `BanData.bin` 解析器（已放弃，勿重启）
- 不要为了「看起来支持迁移」而提供一个静默失败（返回空配置）的导入器
- 不要在配置结构体中保留旧版字段或 `#[serde(alias)]` 兼容别名
- 不要把 IP 地理位置查询放进抓包线程或封停判定路径
