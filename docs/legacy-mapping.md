# 旧版迁移映射

> 记录旧版（易语言）PortGuard 与 Rust 版之间的对应关系，以及当前受阻的部分。

---

## 1. 迁移状态总览

| 迁移对象 | 状态 |
| --- | --- |
| 行为语义（判定顺序、封停逻辑、端口分组） | 已迁移（依据规范文本重建，非逆向源码） |
| 配置数据（`config.dat`） | **受阻** |
| 封停数据（`BanData.bin`） | **受阻** |
| IP 地理位置库（`ip2region_v4.xdb`） | **受阻** |
| 界面形态 | 已变更（Win32 GUI → 内嵌 Web 面板） |

---

## 2. 受阻原因

仓库内**不存在**任何旧版文件：

```text
PortGuard.txt          —— 旧版易语言源码
config.dat             —— 旧版配置
BanData.bin            —— 旧版封停记录
ip2region_v4.xdb       —— IP 地理位置库
```

因果：

- 没有 `PortGuard.txt`，无法逐条核对该工具的真实行为，只能按规范描述重建，
  细节（如窗口默认值、边界条件下的取舍）可能与原版存在出入；
- 没有 `config.dat` 与 `BanData.bin` 的格式样本，**无法编写解析器**——
  盲写解析器等于凭空发明一种二进制格式，正确率不可保证；
- 没有 `ip2region_v4.xdb`，IP 地理位置展示无法实现（该功能本就不参与封停判定）。

因此当前**不提供**「导入旧版配置」功能。凭空写一个只能解析猜测格式的导入器，
比没有这个功能更糟：用户会以为迁移成功了，实际规则全部丢失。

---

## 3. 文件对应关系

| 旧版 | 新版 | 说明 |
| --- | --- | --- |
| `config.dat` | `config.toml` | 二进制 → 纯文本 TOML，可手工编辑、可版本管理 |
| `BanData.bin` | `state/bans.json` | 二进制 → JSON，含 `version` 字段便于后续迁移 |
| 日志文件 | `logs/portguard.log` | 超过 16 MiB 滚动为 `.1` |
| 程序目录 | 相对 exe 目录（`AppPaths::resolve`） | 绿色部署，取不到 exe 时回退当前工作目录 |
| 注册表自启项 | 计划任务 `PortGuard` | 以 `--service` 参数在开机时启动 |

---

## 4. 行为对应关系

| 旧版行为 | 新版实现 | 差异 |
| --- | --- | --- |
| 原始套接字抓包 | `portguard-packet::capture` | 无（保持同一调用顺序） |
| 判定顺序 | `portguard-core::engine` | 无 |
| 危险端口保护（135/137/138/139/445） | `PortGuard-Protect-RiskyPorts-TCP/UDP` 规则 | 无 |
| ICMP Ping 屏蔽 | `PortGuard-Block-ICMPv4/v6` 规则 | 新增 IPv6 规则 |
| 默认排除 VMware 网卡 | `network.include_virtual` 配置项 | **有意差异**：交给用户决定 |
| 无网卡自动选择 | 物理优先 + 非 APIPA 优先 | **新增** |
| 流出方向统计 | `count_outbound`，默认关闭 | **明确化**：默认只统计入站，避免误伤本机外连 |
| Win32 窗口 + Tab + ListView | 内嵌 Web 面板 | **形态变更**（用户决策） |
| 单实例激活已有窗口 | 单实例打开已有实例的面板 | 无窗口形态下的等价实现 |

## 5. 若日后取得旧版文件

### 5.1 有 `PortGuard.txt`（易语言源码）

- 逐条核对判定顺序、阈值语义、端口默认值、白名单匹配规则
- 重点核对：TCP 新连接的判定条件、窗口是滑动还是固定、超限是 `>` 还是 `>=`
- 核对结果写入 `docs/behavior-spec.md` 的「与旧版的差异」表

### 5.2 有 `config.dat`

1. 先确定格式：定长结构体数组 / 带长度前缀的字段 / 键值对
2. 写一次性解析工具（放 `tools/`），**不做运行期兼容分支**
3. 解析结果转成 `Config` 后走 `ConfigStore::save`，由规范化和校验兜底
4. 逐字段与新版默认值对照，差异必须显式记录到本文档

### 5.3 有 `BanData.bin`

1. 解析出 `BanRecord` 列表（IP、原因、时间、是否永久）
2. 写入 `state/bans.json` 的 `bans` 数组
3. 用 `BanManager::restore` 加载，白名单命中的记录会被自动丢弃（预期行为）
4. 启动后核对 `PortGuard-Ban-*` 规则数与记录数是否一致

### 5.4 有 `ip2region_v4.xdb`

- 作为外部数据文件随程序分发（不适合内嵌，文件较大）
- 地理位置**只用于展示**，绝不参与封停判定（规范 22）
- 查询失败时显示「未知」，不得因为查不到地理位置而影响判定

---

## 6. 不应做的事

- 不要凭猜测编写 `config.dat` / `BanData.bin` 解析器
- 不要为了「看起来支持迁移」而提供一个静默失败（返回空配置）的导入器
- 不要把 IP 地理位置查询放进抓包线程或封停判定路径
