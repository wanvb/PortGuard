# PortGuard 行为规格（Behavior Spec）

> 本文档描述 Rust 版 PortGuard 的**实际行为**，以源码为准。
> 与旧版易语言程序存在差异的地方单独标注「与旧版的差异」。

---

## 1. 数据来源与可见性

| 项目 | 说明 |
| --- | --- |
| 抓包方式 | Win32 原始套接字：`socket(AF_INET, SOCK_RAW, IPPROTO_IP)` + `WSAIoctl(SIO_RCVALL, RCVALL_ON)` |
| 可见范围 | SIO_RCVALL 会收到**本网段内全部 IPv4 流量**，不只是本机流量 |
| 过滤责任 | 非本机流量由规则引擎丢弃（`Outcome::Ignored{reason: "not_local_traffic"}`） |
| 权限 | 原始套接字需要管理员；非管理员启动时程序可运行但抓包与封停失效，并在控制台与日志中明确告警 |
| 接收循环 | 单线程阻塞 `recv`，超时 500 ms，便于响应停止请求与退出信号 |
| 时间戳 | 内核不提供收包时间，由运行时在入队前统一打点（`timestamp_ms`） |

- 只监听**一块**网卡的**一个** IPv4 地址（`network.adapter`）。
- 换网卡会清空全部跟踪状态与抓包观测（旧计数在新网卡上无意义）。
- 只解析 **IPv4**：IPv6 流量（如 RDP 的 `[::]:3389` 监听）不参与统计，面板「判定明细」中的解析失败计数会体现这一点。
- 混杂模式的可见性**并非在所有主机上都对称**：部分云主机 / 网卡只放行本机发出的包，入站方向一条都收不到。这种主机必须改用握手响应作为事件来源（见 2.1.2），否则任何端口都不会产生记录。

## 2. 判定流水线

判定是纯函数式决策：输入 `PacketInfo`，输出 `Outcome`。不碰防火墙、不写磁盘。

顺序固定，不可调整：

```text
丢弃 ICMP
  → 是否本机流量（src 或 dst 等于本机 IP）
    → 流出方向是否计入（默认不计入）
      → ① 白名单
        → ② 黑名单
          → ③ 是否受保护端口
            → ④ 是否为新连接（TCP）
              → ⑤ 计数与阈值
                → ⑥ 封停
```

### 2.1 丢弃规则

每条丢弃都必须计入对应的忽略计数（`IgnoreCounters`），并在面板「判定明细」中展示：抓包数在涨但连接列表为空时，用户必须能分辨是抓包链路问题还是判定条件问题，不得静默丢弃。

| 条件 | 结果 | 忽略计数 |
| --- | --- | --- |
| `protocol == ICMP` | `Ignored{icmp_unsupported}`（ICMP 只由系统级 Ping 屏蔽处理） | `icmp` |
| `src != 本机 IP && dst != 本机 IP` | `Ignored{not_local_traffic}` | `not_local` |
| 流出方向、`count_outbound == false` 且非握手响应 | `Ignored{outbound_ignored}` | `outbound` |
| TCP 且不满足当前事件来源（见 2.5） | `Ignored{not_new_connection}` | `not_new_connection` |
| 端口不在任何保护组 | `Ignored{port_not_protected}` | `port_not_protected` |

**流出方向默认不计入阈值。** 原因：暴力破解与端口扫描的特征是「外部 → 本机受保护端口」的入站请求；把本机主动外连计入会误伤正常业务。

**唯一例外是握手响应（SYN+ACK）**：它虽然由本机发出，但只可能是「别人连到本机受保护端口」时本机的应答，因此在 `protect.count_accept` 打开时放行并按一次连接事件处理（见 2.5）。

### 2.1.1 抓包观测与解析诊断

判定之前先把每个包记入观测表（`portguard-core::observe`），按「方向 + 协议 + 本机端口 + TCP 标志类别」计数，面板「抓包观测」展示次数最高的 12 条。

- 观测表**不参与判定**，只用于回答「这个端口的包到底有没有被收到」。
- 条目上限 256，超出后只累加溢出计数，长期运行内存不增长。
- 抓包层解析失败（非 IPv4 / 分片 / 畸形包）单独计数并保留最多 3 条十六进制样本，与观测表一起展示，用于区分「没抓到」与「抓到但解析器丢了」。
- 切换网卡、重新开始抓包时清空观测表。

### 2.1.2 两条前提的自动回退（`protect.count_accept`）

混杂模式（`SIO_RCVALL`）在部分云主机 / 网卡上只能看到**本机发出**的包，入站方向一个都收不到。此时若只认入站 `SYN`，无论客户端怎么连都不会产生任何记录（旧版程序正是因此在 SYN+ACK 上累加）。

`protect.count_accept` **默认为 `true`**，这些主机开箱即用。配置里是 `false`
（旧版本留下的值，或用户在设置页显式关闭）时，运行期每 5 秒检查一次，
**两个条件同时成立**才自动切换事件来源：

- 受保护的 TCP 端口上，入站纯 `SYN` 一条都没有；
- 同一个端口上已出现本机发出的 `SYN+ACK`（只有真的有人连进来才会有）。

切换后写入事件流与日志说明原因。该判定**只做一次**：

- 用户在设置页显式改过 `protect.count_accept`（从开改到关或反之）即视为已决定，运行期永不覆盖；
- 自动切换的结果在切换网卡后会重新判定（新网卡的混杂模式行为可能完全不同）。

### 2.2 对端与受保护端口的确定

- 入站包：`peer = src`，`service_port = dst_port`
- 出站包（仅在 `count_outbound == true` 时）：`peer = dst`，`service_port = src_port`

### 2.3 ① 白名单（最高优先级）

- 命中即返回 `Outcome::Whitelisted`，**不再执行任何后续步骤**（不参与阈值判定）。
- 白名单优先于黑名单：同一 IP 同时出现在两份名单中时按白名单处理。
- 白名单 IP 永远不会被自动封停、黑名单封停或手动封停。
- **但白名单地址的访问仍写入跟踪表（仅展示用）**：条件是该包本身可计数（TCP 为 `SYN && !ACK`、UDP 为任意报文）且端口属于某个保护组。记录只用于面板展示 `WHITELIST` 状态，永不累加阈值、永不封停；否则面板的 `WHITELIST` 状态永远不可达，用户会误以为「白名单里的地址从来没连过」。
- 白名单访问**非保护端口**不产生任何记录，避免连接列表被无关行淹没。

### 2.4 ② 黑名单

- 命中即返回 `Outcome::BlacklistBan`。
- **不写入跟踪表**：黑名单封停与阈值统计相互独立。

### 2.5 ③ ④ 端口与新连接

端口分三组，各自独立配置阈值：

| 组 | 配置段 | 默认端口 | 默认阈值 |
| --- | --- | --- | --- |
| TCP | `[protect.tcp]` | 3389 | 5 |
| WEB | `[protect.http]` | 80, 443 | 10 |
| UDP | `[protect.udp]` | 3389 | 5 |

TCP 新连接判定：`syn == true && ack == false`。其余标志组合（含单独 ACK、FIN/ACK）一律 `Ignored{not_new_connection}`。

**事件来源**由 `protect.count_accept` 决定：

| 取值 | 事件来源 | 适用场景 |
| --- | --- | --- |
| `false` | 入站 `SYN && !ACK` | 混杂模式能收到入站包的常规主机 |
| `true`（默认） | 本机发出的 `SYN+ACK` | 混杂模式收不到入站包的云主机（见 2.1.2 自动回退） |

两种口径互斥，同一连接只会被计一次，不会重复累加。`count_accept` 打开时**只放行握手响应**（入站 `SYN` 记入 `not_new_connection`），本机主动外连（纯 SYN、ACK 等）仍按 2.1 丢弃，因此不会误伤正常外连业务。

UDP 无连接建立过程，**每个报文都计一次访问**。

**端口同时属于 TCP 组与 WEB 组时，两组各自独立计数**，任意一组达到阈值即封停；都未达到时以 TCP 组的结果作为代表返回。

### 2.6 ⑤ 阈值语义

- 计数键：`(peer IP, 服务端口, 组别)`
- 计数为**累计值**，不做滑动窗口：只要该来源还在活动就一直累加
- 判定条件为 `count >= max_attempts`
- 即：阈值 N 表示**第 N 次连接即封停**
- 归零只有一条路径：该条目连续空闲超过跟踪保留期（当前 10 分钟）被 `prune` 回收，
  下次出现时从 0 重新计数。因此「间隔几十秒反复连接」会迅速累计并封停，
  而「隔天来一次的正常访问」不会跨天叠加。
- 因果：滑动窗口口径下，稀疏但反复的连接每次都滑出窗口，累计值永远够不到阈值，
  表现为「面板上累计次数一直在涨却从不封停」——这正是要避免的漏封。

## 3. 封停状态机

### 3.1 记录字段

`BanRecord`：`ip`、`protocol`、`service_port`、`remote_port`、`attempt_count`、`created_at_ms`、`expires_at_ms`、`permanent`、`reason`、`rule_name`。

### 3.2 永久性判定

```text
permanent = 配置的 ban.permanent || reason == Manual
```

即：**手动封停默认永久**，即使全局配置为临时封停。

### 3.3 封停原因（`BanReason`）

`TcpThreshold` / `WebThreshold` / `UdpThreshold` / `Blacklist` / `Manual`。

### 3.4 升级与降级

| 场景 | 行为 |
| --- | --- |
| 已永久封停，再次临时封停 | **保留原有永久记录**，不作任何修改 |
| 已临时封停，再次永久封停 | 升级为永久，`created_at_ms` 更新 |
| 已封停，再次同性质封停 | 覆盖记录 |

### 3.5 白名单硬校验（不可绕过）

所有封停路径（阈值、黑名单、手动、重启恢复）最终都必须经过 `BanManager::ban`，该方法在白名单命中时返回 `Err`，**调用方必须把错误暴露到面板与日志**，不得静默忽略。

### 3.6 到期回收

- 临时封停到期后由运行时定时任务（每 5 秒）调用 `take_expired` 取出并移除记录。
- 取出后**必须显式解封**对应防火墙规则，否则规则泄漏。
- 永久封停 `expires_at_ms == None`，永不到期。

### 3.7 跟踪行保留

- 封停成功后**不删除**跟踪表中的对应行，面板状态显示为 `BANNED` / `PERMANENT`。
- 因果：删行后用户只看得到「封停记录」，看不到该 IP 打的是哪个端口、累计多少次，排查时缺少上下文。
- 该行仍按连接列表 TTL（5 分钟未再出现）从展示中消失，跟踪表本身按 10 分钟保留期回收，不会无界增长。
- 解封后若仍在 TTL 内，该行自动回落为 `TRACKING`。

## 4. 解封语义

| 触发 | 行为 |
| --- | --- |
| 临时封停到期 | 删除记录 + 删除对应防火墙规则 |
| 面板手动解封 | 删除记录 + 删除对应防火墙规则 |
| 加入白名单 | 该地址若已封停，**立即解封**并删除规则 |
| 程序启动清理 | 扫描系统中全部 `PortGuard-Ban-` 规则，删除无对应记录的孤儿规则 |
| 程序退出 | 持久化封停记录，**不**删除防火墙规则（重启后恢复并继续生效） |

## 5. 防火墙规则

| 规则名 | 归属前缀 | 用途 |
| --- | --- | --- |
| `PortGuard-Ban-<ip>` | `PortGuard-Ban-` | 单个 IP 封停，动作 = 禁止，远端 IP = `<ip>/32` |
| `PortGuard-Protect-RiskyPorts-TCP` | `PortGuard-` | 危险端口保护（TCP） |
| `PortGuard-Protect-RiskyPorts-UDP` | `PortGuard-` | 危险端口保护（UDP） |
| `PortGuard-Block-ICMPv4` | `PortGuard-` | 禁止 Ping（IPv4） |
| `PortGuard-Block-ICMPv6` | `PortGuard-` | 禁止 Ping（IPv6） |

不变式：

- 解封只按**规则名**删除，绝不按 `remoteip` 匹配删除（会误删系统或第三方规则）。
- 规范化清理只涉及 `PortGuard-` 前缀的规则。
- 后端为 `netsh advfirewall`，进程调用不经 shell（`Command::new("netsh")`），参数严格构造，禁止命令注入。
- **防火墙操作失败时不得假装成功**：内存状态只在系统调用成功后更新；失败要写事件、写日志并让用户看到。

## 6. 系统级保护

### 6.1 危险端口保护

- 覆盖端口：`135, 137, 138, 139, 445`
- 通过独立规则对**入站**流量放行策略改为阻止
- 与 IP 封停相互独立，关闭时只删除对应规则

### 6.2 Ping 屏蔽

- 对 IPv4 与 IPv6 各建一条规则，阻止 ICMP Echo Request
- ICMP 数据包不参与 IP 封停判定

### 6.3 开机自启动

- 以 **Windows 系统服务**实现：面板勾选时 `CreateServiceW` 注册（`SERVICE_AUTO_START`、
  账号 LocalSystem、启动参数 `--service`），取消勾选时 `DeleteService` 卸载
- 只注册不立即启动：本项的含义是「开机自动启动」，由 SCM 在下次开机时拉起；
  立即启动会与用户当前实例争抢单实例守卫
- 服务进程必须完成 SCM 握手（`StartServiceCtrlDispatcherW` → 上报 `SERVICE_RUNNING`），
  因此主程序在读完参数后**第一件事**就是进入服务分发，早于此的返回都会变成
  「1053 服务没有及时响应启动或控制请求」
- `sc stop` / 关机经服务控制处理器置退出标志，与 Ctrl+C 走同一套收尾流程
- `--service` 模式不自动打开浏览器、不建托盘（会话 0 没有交互桌面）

### 6.4 控制台窗口（默认隐藏）

进程形态是「托盘 + 内嵌 Web 面板」，不需要常驻的黑窗口，因此：

- **双击启动**（控制台只挂着本进程）时隐藏控制台窗口，任务栏只留托盘图标；
  托盘右键菜单（打开面板 / 暂停保护 / 退出）功能完全不变
- **从 cmd / PowerShell 启动时不隐藏**：此时控制台上还挂着用户自己的 shell，
  隐藏会连带把它一起藏掉；判定依据是 `GetConsoleProcessList` 返回的挂载进程数必须为 1
  （查询失败返回 0 同样不隐藏——宁可留个黑窗口，也不能藏用户的窗口）
- `--console` 显式保留窗口，便于排查启动期问题；`--service` 运行在会话 0，本就没有控制台
- 隐藏后终端里看不到任何输出，因此：**启动期致命错误必须弹对话框**（不得表现为「双击没反应」），
  启动期告警（非管理员、自动开始保护失败）改用托盘气泡重复一次
- 隐藏窗口不等于放弃控制台：进程仍挂着控制台，注销 / 关机时 `SetConsoleCtrlHandler`
  仍会收到事件并走上完整收尾（清理托盘图标与计划外残留规则）；以服务运行时没有控制台，
  退出请求由服务控制处理器置同一标志位

## 7. RDP 客户端计算机名保护

- 依据 RDP 会话的客户端计算机名决定是否断开
- 客户端白名单为空表示**不限制**
- 匹配不区分大小写
- 定时任务每 15 秒扫描一次，仅在产生动作时才写事件与日志
- 不在窗口回调/会话回调中执行长操作

## 8. 配置语义

### 8.1 默认值来源必须同源

`Config` 的 `Default` 实现直接委托 `Config::with_defaults()`，`ProtectConfig` 等子结构的 `Default` 必须与配置文件模板一致。

因果：`#[serde(default)]` 在解析用户手写的局部配置时走的就是这些 `Default`。若子结构默认给空端口，用户只写 `[panel]` 一段就会让程序**静默失去全部保护能力**。

### 8.2 规范化

- 端口：剔除 0、排序、去重
- `max_attempts == 0` → 1；`ban.duration_seconds == 0` → 60；`geo.db` 为空 → 回退默认文件名
- 名单行：去空白、去空行、去 `#` 注释行
- 备注：去控制字符与首尾空白、按字符截断到 64；空备注不写进文件；键已不在端口 / 名单里的**孤儿备注一并清除**
  （端口保持 `Vec<u16>`、名单保持 `Vec<String>`，备注是与之平行的纯展示映射，见 8.5）
- `config_version` 低于当前版本时抬到当前版本
- 面板监听地址若仍等于旧默认值 `127.0.0.1:18080`，迁移为 `DEFAULT_PANEL_BIND`（`127.0.0.1:58080`）
- TCP-WEB 累计连接阈值若仍等于旧默认值 `10`，迁移为 `DEFAULT_WEB_MAX_ATTEMPTS`（`300`）。
  旧阈值会封掉仅加载 CSS / JS / 图片的正常访客；用户想收紧回 10 在面板里改即可
- 以上迁移由 `Config::migrate()` 单独完成（与 `normalize` 分开），返回中文说明清单；
  **主程序必须在启动时把迁移结果写回 `config.toml`**：只改内存的话，第二个实例会拿文件里的旧端口
  去开面板，而运行中的实例已经换到新端口，用户看到的就是「页面打不开」
- 迁移判定一律按**值**而非结构版本：`normalize` 早于迁移执行，已经把 `config_version` 抬到当前版本，
  按版本判定永远不会命中

### 8.3 保存流程

```text
normalize → validate → 落盘 → 应用到内存
```

- 任一环节失败则**内存状态保持不变**（不会出现「界面显示新配置、实际还是旧配置」）
- 非法白名单/黑名单规则整体拒绝，不写入半条
- **三组保护端口全空时拒绝保存**：此时程序「看着在跑」却不会统计、也不会封停任何端口，属于静默失效；错误文案必须点明「TCP / TCP-WEB / UDP 至少填写一个端口」
- 启动时若三组端口全空，写入一条 `warn` 事件（面板可见）与一条告警日志，不静默继续
- 网卡变更需要真正重启抓包，失败必须让用户看到
- `protect.count_accept` 被显式改动时，同时把该 IP 标记为「已决定」，运行期不再自动改写它（见 2.1.2）

### 8.4 热更新

- 白名单解析失败时**保留旧值**，不静默清空既有规则
- 更新白名单**不会**自动解封既有记录（除显式调用「加入白名单」接口外），避免改配置顺手放行攻击源

### 8.5 备注（`notes`）

- 三组保护端口与白/黑名单规则各可写一条备注，用于回答「这个端口 / 这条规则是谁在用的」
  （服务器上 frp 穿透的端口一多，光看端口号分不清业务）。
- 备注是**纯展示元数据**：不参与端口匹配、名单解析、阈值判定、封停与配置校验，与地理位置同口径（规范 22）。
  因此它与 `ports` / `whitelist` / `blacklist` 分开存储，判定链路完全不感知它的存在。
- 键只能是字符串（TOML 的 map 键不支持整数）：端口用十进制字符串，名单用规则原文；
  含 `.` `*` `/` 的键在写盘时自动加引号，手改配置文件时必须保留引号，否则会被解析成分层表而整份配置报错。
- 单条备注上限 64 字符；空备注不落盘。
- **孤儿的唯一清理点是 `Config::normalize`**：端口 / 规则被删掉后，其备注在下次保存时一并消失；
  不清理的话备注会永远留在 `config.toml` 里，用户日后加回同一个端口还会看到过期备注。
- 备注随 `ConnectionView` / `BanView` 的 `port_note` / `ip_note` 下发到面板，前端只做内联显示，不改变任何判定相关的展示口径。

## 9. 持久化

| 文件 | 内容 | 写入时机 |
| --- | --- | --- |
| `config.toml` | 配置 | 保存配置时 |
| `state/bans.json` | 封停记录 | 每次封停/解封后 |
| `logs/portguard.log` | 日志 | 实时追加 + 内存镜像 |

启动恢复顺序：加载配置 → 启动日志 → 获取单实例 → 恢复封停记录 → 清理孤儿规则 → 自动选网卡 → 启动抓包。

恢复时的两条规则：

- 白名单命中的记录**直接丢弃**（保证「白名单永远优先」在重启后依然成立）
- **已到期的记录不丢弃**，必须走 `take_expired` 显式解封，否则崩溃时残留的防火墙规则会泄漏

## 10. 不变式清单（Invariants）

以下条件在任何时刻都必须成立，违反即为缺陷：

1. 白名单 IP 的封停记录数为 0。
2. 系统中不存在**无对应封停记录**的 `PortGuard-Ban-*` 规则。
3. 封停记录数与 `PortGuard-Ban-*` 规则数一致（失败时会记录差异并告警）。
4. 面板显示的配置与 `config.toml` 内容一致。
5. 抓包线程不在持有锁时执行 netsh 调用或磁盘写入。
6. 同一攻击源在封停动作完成前不会重复排队。
7. 面板只监听回环地址；非回环绑定需用户显式配置。
8. 前端所有数据经 `textContent` 写入 DOM。
9. 每个被丢弃的数据包都归入 `IgnoreCounters` 的五个分类之一，不存在无计数的静默丢弃路径。
10. 保护端口绝不长期为空：保存配置时被校验拦下，历史遗留的空配置在启动时告警。
11. 白名单地址的跟踪行永不携带封停记录。
12. 观测表与解析失败计数**只增不减地反映真实抓到的包**，绝不参与任何判定，也不因判定结果而丢弃记录。
13. 自动切换连接事件来源只在「无入站 SYN + 有出站 SYN+ACK」同时成立时发生，且用户显式设置过就永不覆盖。
14. 备注（`notes`）绝不参与任何判定与落盘校验：端口匹配、名单解析、阈值、封停、`validate`
    都不得读取它；`config.toml` 中的备注键必然对应一个现存端口或名单规则（无孤儿）。

## 11. 与旧版的差异

| 项目 | 旧版（易语言） | 新版 |
