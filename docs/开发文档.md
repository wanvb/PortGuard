# CLAUDE.md — PortGuard Rust 重写项目开发总控规范

> 项目目标：从现有易语言版本 `PortGuard` 反向梳理需求，以 Rust 从零重写一个功能等价、结构现代、可维护、可测试的 Windows 服务器端口保护工具。
>
> 本文件是 **Claude Code / Claude Agent 的长期开发控制文件**。后续所有开发工作都必须以本文件为最高项目级执行规范之一。
>
> 原始参考源码：本项目随附的易语言源码 `PortGuard.txt`。它是行为参考，不是 Rust 代码模板。严禁机械逐行翻译。

---

## 0. 最高优先级规则

### 0.1 目标平台

必须优先保证以下系统：

- Windows 7 SP1 x64
- Windows Server 2008 R2（如实现成本可控，应保持兼容）
- Windows Server 2012 / 2012 R2
- Windows 10
- Windows 11

第一阶段目标为 **Windows 7 SP1 x64 + Windows Server 2012 R2 x64**。

### 0.2 UI 形态（内嵌 Web 面板）

界面采用**内嵌 Web 控制面板**：程序本身是无窗口的 exe（控制台窗口默认隐藏，只留系统托盘），
启动后在回环地址起一个 HTTP 服务，用户用浏览器访问查看与控制。
详细规格见 `docs/web-ui-spec.md`，控制台窗口的隐藏规则见 `docs/behavior-spec.md` 6.4。

必须：

- 前端资源（HTML / CSS / JS）在编译期内嵌进 exe（`include_str!`），实现**单文件部署**
- 前端为纯 ES6 + `fetch`，无构建步骤、无第三方库
- 只监听回环地址（默认 `127.0.0.1:58080`），无登录口令
- 强制 Host 校验与 Origin 校验，防 DNS rebinding 与 CSRF
- 所有动态数据经 `textContent` 写入 DOM，禁止 `innerHTML` 拼接

不要使用：

- Tauri / Electron / WebView2 / wry 等需要额外 runtime 的桌面壳
- egui / iced / Qt / GTK 等需要随程序分发的 GUI 框架
- Win32 原生控件（旧方案，已废弃，见下）

原因：

- 目标机包含 Windows 7 SP1 / Server 2008 R2，不能把现代 Web UI runtime 作为基础依赖；
  浏览器是**目标机已有的**外部程序，不需要随本程序部署任何 runtime；
- 单 exe + 浏览器访问避免了 Win32 控件在不同系统主题 / DPI 下的布局问题；
- 无窗口形态让程序可以直接注册为 Windows 服务、以 LocalSystem 身份在会话 0 运行。

控制台窗口**默认隐藏**：双击启动时只留托盘图标（右键菜单照旧控制），
从 cmd 启动或加 `--console` 时保留窗口便于排查。隐藏后启动期的致命错误改弹对话框，
告警改走托盘气泡 —— 不允许「双击没反应」这种静默失败。规则见 `docs/behavior-spec.md` 6.4。

安全前提：面板无口令，其安全性完全依赖「仅回环 + 请求头校验」，因此上述两条校验
属于硬性要求，不得为了调试方便而关闭。

### 0.3 不允许改变原始安全语义

Rust 重写必须保持以下核心行为：

1. 选择指定本机网卡/IP。
2. 监听流入/流出 IPv4 数据包。
3. 解析 IPv4、TCP、UDP。
4. 对目标保护端口进行连接行为统计。
5. 白名单永远优先于黑名单和自动封停。
6. 黑名单命中后可立即封停。
7. TCP / TCP-WEB / UDP 可以分别设置：
   - 保护端口列表
   - 最大重连次数（累计值，达到即封停）
8. 达到阈值后进入封停池。
9. 封停使用 Windows Firewall。
10. 封停有：
    - 临时封停
    - 永久封停
11. 到期自动解封。
12. 程序重启后恢复封停列表。
13. 支持手动封停、手动解封、加入白名单。
14. 支持 Windows 防火墙危险端口保护。
15. 支持 ICMP Ping 屏蔽。
16. 支持开机自动启动。
17. 支持系统托盘。
18. 支持 RDP 客户端计算机名白名单。
19. 支持日志。
20. 支持 IP 地理信息展示，但地理信息不得参与核心封停判断。

# 4. 连接检测逻辑

原程序的核心统计逻辑必须抽象成可测试的规则引擎。

原行为：

```text
Packet
 ↓
ignore whitelist
 ↓
blacklist?
 ├─ yes → immediate ban
 └─ no
 ↓
protected TCP port?
protected WEB port?
protected UDP port?
 ↓
connection tracker
 ↓
count within configured time window
 ↓
count > threshold?
 ├─ yes → ban
 └─ no → keep tracking
```

注意：

### 4.1 TCP 新连接判断

原源码主要观察 SYN / ACK。

Rust 实现必须明确：

```text
SYN && !ACK
```

代表连接请求。

`SYN+ACK` 是响应，不应被错误地当成新的客户端连接。

但是不要简单复制原程序所有注释；必须用单元测试验证行为。

### 4.1.1 混杂模式收不到入站包时的回退

实测发现：部分云主机的 `SIO_RCVALL` **只能看到本机发出的包**，入站方向一个都收不到
（旧版易语言程序因此在 SYN+ACK 上累加）。此时只认入站 `SYN` 会导致任何端口都没有记录。

处理方式（详细规格见 `docs/behavior-spec.md` 2.1.1 / 2.1.2）：

- 判定之前先把每个包记入**抓包观测表**（`portguard-core::observe`），面板展示 Top 12，
  用于回答「这个端口的包到底有没有被抓到」；
- 抓包层解析失败单独计数并保留十六进制样本，用于排除「抓到了但解析器丢了」；
- 提供 `protect.count_accept` 开关（**默认为 `true`**）：打开后改用本机发出的 `SYN+ACK` 作为连接事件来源；
- 运行期在两个条件同时成立时**自动**打开它并说明原因：受保护 TCP 端口无入站 SYN，
  且同端口出现本机发出的 SYN+ACK。该判定只做一次，用户显式设置过就永不覆盖。

两种口径互斥，同一次连接只会被计一次。

### 4.2 TCP-WEB

“WEB”是原程序对另一组 TCP 保护端口的逻辑分类。

不要硬编码“80/443”。

用户配置决定哪些端口属于 WEB。

**默认阈值必须远高于普通 TCP**：默认 `max_attempts = 300`（普通 TCP / UDP 为 5）。
一次页面访问会连带 CSS、JS、图片、接口等数十个连接，阈值取 10 之类的低位会把

正常访客直接秒封；Web 类服务按「连接数天然多、单连接风险低」设阈值，宁可放宽。

结构版本 3 起，仍等于旧默认值 10 的配置由 `Config::migrate()` 自动放宽到 300。

### 4.3 UDP

UDP 不存在 TCP 式连接建立。

因此 Rust 中应明确把 UDP 的“访问/报文次数”作为统计事件，而不是伪造 TCP 状态机。

# 5. 白名单 / 黑名单

原程序支持：

```text
192.168.1.10
192.168.1.1-192.168.1.100
192.168.1.*
```

Rust 必须支持上述格式。

建议统一解析为：

```rust
struct IpRange {
    start: u32,
    end: u32,
}
```

白名单：

```text
Vec<IpRange>
```

黑名单：

```text
Vec<IpRange>
```

判断：

```text
ip in whitelist → ALWAYS ALLOW
ip in blacklist → IMMEDIATE BAN
```

## 5.1 规则优先级

严格定义：

```text
Whitelist
    ↓
Blacklist
    ↓
Protected Port
    ↓
Connection Threshold
    ↓
Ban
```

即：

> 白名单优先级最高。

不得出现：

```text
白名单 IP 因重连次数过多而被自动封停
```

# 8. Windows Firewall

这是整个项目的重要 Windows 适配层。

## 8.1 第一原则

所有防火墙操作必须集中在：

```text
portguard-firewall
```

UI 和核心业务不得执行：

```text
Command::new("netsh")
```

### Firewall API

建议定义：

```rust
trait FirewallBackend {
    fn is_enabled(&self) -> Result<bool>;
    fn block_ip(&self, ip: IpAddr) -> Result<()>;
    fn unblock_ip(&self, ip: IpAddr) -> Result<()>;
    fn block_port(&self, protocol: Protocol, ports: &[u16]) -> Result<()>;
    fn unblock_port(&self, protocol: Protocol, ports: &[u16]) -> Result<()>;
    fn rule_exists(&self, rule_name: &str) -> Result<bool>;
}
```

## 8.2 防火墙后端优先级

第一选择：

- Windows Firewall COM API / `INetFwPolicy2`

兼容性备用：

- `netsh advfirewall`

如果使用 `netsh`：

- 参数必须严格构造；
- 禁止拼接未经验证的任意用户输入；
- IP / port 必须经过解析；
- 必须检查 exit code；
- 必须记录 stderr；
- 必须避免命令注入。

## 8.3 IP 封停规则命名

不要完全复制原程序：

```text
banIP
```

推荐：

```text
PortGuard-Ban-IP-<normalized-ip>
```

但必须考虑 Windows Firewall rule name 长度与清理问题。

更稳妥的方案：

```text
PortGuard-Ban-IP-<hash>
```

同时在本地数据库保存：

```text
rule_id
ip
created_at
expires_at
permanent
```

### 8.4 不能删除非本程序规则

这是硬性安全要求。

PortGuard 只能删除自己创建的规则。

不得：

```text
按 remoteip=xxx
```

无条件删除系统已有规则。

导航项带计数徽标（当前连接数、封停数）。所有操作就地以 toast 或错误条反馈，

# 18. 面板 / Core 解耦

严禁：



`PortGuardApi` 是面板唯一能看到的东西，定义在 `portguard-core::api`。

# 19. 线程模型

```text
主线程（托盘消息循环；控制台窗口默认隐藏，仅保留退出信号接管）
│
├── 托盘图标与菜单
├── 退出信号（Ctrl+C 只置标志位）
└── 每秒刷新托盘提示与菜单状态
       ↑
       │
执行线程（串行处理所有系统动作）
│
├── netsh 防火墙封停 / 解封
├── bans.json 落盘
└── 启动时清理孤儿规则

抓包线程
│
├── recv 循环（超时 500ms）
└── 锁内判定 + 入队（只做这两件事）

HTTP 工作线程（每个连接一个）
└── 读内存快照 / 投递动作，绝不阻塞

定时任务（挂在执行线程上）
├── 每 5 秒：到期解封 + 跟踪表清理
└── 每 15 秒：RDP 客户端计算机名巡检
```

不要让抓包线程直接调用防火墙或写磁盘。

不要在 HTTP 工作线程：

- recv
- firewall command
- 文件大量写入
- IP 数据库查询
- 大量表格重建

# 22. IP 地理信息

原程序使用：

```text
ip2region_v4.xdb
```

Rust 版本（**已实现**，`crates/portguard-geo`）：

- 沿用同一 xdb v3 数据库文件，与旧版同格式，无需迁移；
- 查询只访问内存中的字节切片，按向量索引 + 段索引二分查找，开销为微秒级；
- **只用于展示，绝不参与封停判定**——判定路径（白名单 / 黑名单 / 端口 / 阈值）完全不接触本模块；
- 库缺失、IP 非法、检索未命中一律显示「未知」，不影响任何安全逻辑；
- 查询发生在控制面板拼装视图时（运行期锁**之外**），不进抓包线程。

UI 显示：

```text
中国 · 江苏省 · 南京市 · 中国电信
```

即数据库字段 `国家|省份|城市|ISP|国家代码` 中跳过占位符 `0` 后的非空项；
保留地址段显示为「保留地址」。

# 26. 安全原则

这是服务器防护软件，错误比普通桌面软件更危险。

必须：

### 26.1 Fail safe

防火墙操作失败：

- 不假装成功；
- UI 显示错误；
- 日志记录；
- 保留内部状态与实际 Firewall 状态的差异。

### 26.2 不误封白名单

任何路径：

```text
manual ban
blacklist
threshold
restore
```

都必须最终检查：

```text
whitelist.contains(ip)
```

### 26.3 防止规则泄漏

程序崩溃/异常后：

- 不删除用户已有 Firewall 规则；
- 不误删系统规则；
- 自己创建的规则可被恢复/清理。

# 43. UI 更新策略

面板不做服务端推送，全部由浏览器按 **1 秒**间隔轮询 `GET /api/state` 聚合接口。

不要为每类数据各发一个请求，也不要用短于 1 秒的间隔：抓包量可达每秒数千包，
随包推送只会把浏览器与后端一起拖住。

```text
抓包线程 → 内存计数 →（浏览器每秒一次 GET /api/state）→ 整表重绘
```

封停 / 解封是用户可感知的关键动作，操作完成后立即触发一次刷新，不等下一个轮询周期。

轮询失败时保留上一次数据并提示「连接已断开」，不得清空表格（否则一次网络抖动
会让用户以为封停列表被清空了）。

# 44. 防止 UI 卡死

HTTP 工作线程禁止：

```text
Sleep
recv
Command::output
大量文件读写
大量 IP 查询
大量 Firewall API
```

`PortGuardApi` 的每个方法必须快速返回：只做「读内存快照」或「投递动作」，
真正的 netsh 调用与磁盘写入交给执行线程（见第 19 节）。

封停、解封、加名单等需要执行系统命令的操作一律「投递后立即返回」，
结果通过下一次轮询体现。

导航改为顶部常驻横排（原侧边栏占用约 250px 横向空间，笔记本窄屏下表格被迫横向滚动），

这比原程序的单表格混合展示更容易理解。

# 49. Claude 的最终工作原则
