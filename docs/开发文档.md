# CLAUDE.md — PortGuard Rust 重写项目开发总控规范

> 项目目标：从现有易语言版本 `PortGuard` 反向梳理需求，以 Rust 从零重写一个功能等价、结构现代、可维护、可测试的 Windows 服务器端口保护工具。
>
> 本文件是 **Claude Code / Claude Agent 的长期开发控制文件**。后续所有开发工作都必须以本文件为最高项目级执行规范之一。
>
> 原始参考源码：本项目随附的易语言源码 `PortGuard.txt`。它是行为参考，不是 Rust 代码模板。严禁机械逐行翻译。

---

## 0. 最高优先级规则

### 0.1 目标平台

必须优先保证以下系统：

- Windows 7 SP1 x64
- Windows Server 2008 R2（如实现成本可控，应保持兼容）
- Windows Server 2012 / 2012 R2
- Windows 10
- Windows 11

第一阶段目标为 **Windows 7 SP1 x64 + Windows Server 2012 R2 x64**。

### 0.2 UI 硬性约束

必须使用：

- 原生 Win32 API
- 原生 Windows Controls
- 或基于 Win32 / Windows Controls 的 Rust 封装

推荐优先：

- `windows` crate
- 原生 `HWND`
- `CreateWindowExW`
- `WC_TABCONTROL`
- `WC_LISTVIEWW`
- `WC_COMBOBOXW`
- `WC_EDITW`
- `WC_BUTTONW`
- `WC_STATICW`
- `WC_STATUSBARW`
- `Shell_NotifyIconW`

不要使用：

- WebView / WebView2
- Electron
- Tauri
- Qt
- GTK
- egui
- iced
- wry
- 任何要求现代 Web Runtime 的 GUI

原因：目标服务器包含 Windows 7 / Windows Server 2012，不能把现代 Web UI runtime 作为基础依赖。

### 0.3 不允许改变原始安全语义

Rust 重写必须保持以下核心行为：

1. 选择指定本机网卡/IP。
2. 监听流入/流出 IPv4 数据包。
3. 解析 IPv4、TCP、UDP。
4. 对目标保护端口进行连接行为统计。
5. 白名单永远优先于黑名单和自动封停。
6. 黑名单命中后可立即封停。
7. TCP / TCP-WEB / UDP 可以分别设置：
   - 统计时间窗口
   - 最大重连次数
8. 超过阈值后进入封停池。
9. 封停使用 Windows Firewall。
10. 封停有：
    - 临时封停
    - 永久封停
11. 到期自动解封。
12. 程序重启后恢复封停列表。
13. 支持手动封停、手动解封、加入白名单。
14. 支持 Windows 防火墙危险端口保护。
15. 支持 ICMP Ping 屏蔽。
16. 支持开机自动启动。
17. 支持系统托盘。
18. 支持 RDP 客户端计算机名白名单。
19. 支持日志。
20. 支持 IP 地理信息展示，但地理信息不得参与核心封停判断。

# 4. 连接检测逻辑

原程序的核心统计逻辑必须抽象成可测试的规则引擎。

原行为：

```text
Packet
 ↓
ignore whitelist
 ↓
blacklist?
 ├─ yes → immediate ban
 └─ no
 ↓
protected TCP port?
protected WEB port?
protected UDP port?
 ↓
connection tracker
 ↓
count within configured time window
 ↓
count > threshold?
 ├─ yes → ban
 └─ no → keep tracking
```

注意：

### 4.1 TCP 新连接判断

原源码主要观察 SYN / ACK。

Rust 实现必须明确：

```text
SYN && !ACK
```

代表连接请求。

`SYN+ACK` 是响应，不应被错误地当成新的客户端连接。

但是不要简单复制原程序所有注释；必须用单元测试验证行为。

### 4.2 TCP-WEB

“WEB”是原程序对另一组 TCP 保护端口的逻辑分类。

不要硬编码“80/443”。

用户配置决定哪些端口属于 WEB。

### 4.3 UDP

UDP 不存在 TCP 式连接建立。

因此 Rust 中应明确把 UDP 的“访问/报文次数”作为统计事件，而不是伪造 TCP 状态机。

# 5. 白名单 / 黑名单

原程序支持：

```text
192.168.1.10
192.168.1.1-192.168.1.100
192.168.1.*
```

Rust 必须支持上述格式。

建议统一解析为：

```rust
struct IpRange {
    start: u32,
    end: u32,
}
```

白名单：

```text
Vec<IpRange>
```

黑名单：

```text
Vec<IpRange>
```

判断：

```text
ip in whitelist → ALWAYS ALLOW
ip in blacklist → IMMEDIATE BAN
```

## 5.1 规则优先级

严格定义：

```text
Whitelist
    ↓
Blacklist
    ↓
Protected Port
    ↓
Connection Threshold
    ↓
Ban
```

即：

> 白名单优先级最高。

不得出现：

```text
白名单 IP 因重连次数过多而被自动封停
```

# 8. Windows Firewall

这是整个项目的重要 Windows 适配层。

## 8.1 第一原则

所有防火墙操作必须集中在：

```text
portguard-firewall
```

UI 和核心业务不得执行：

```text
Command::new("netsh")
```

### Firewall API

建议定义：

```rust
trait FirewallBackend {
    fn is_enabled(&self) -> Result<bool>;
    fn block_ip(&self, ip: IpAddr) -> Result<()>;
    fn unblock_ip(&self, ip: IpAddr) -> Result<()>;
    fn block_port(&self, protocol: Protocol, ports: &[u16]) -> Result<()>;
    fn unblock_port(&self, protocol: Protocol, ports: &[u16]) -> Result<()>;
    fn rule_exists(&self, rule_name: &str) -> Result<bool>;
}
```

## 8.2 防火墙后端优先级

第一选择：

- Windows Firewall COM API / `INetFwPolicy2`

兼容性备用：

- `netsh advfirewall`

如果使用 `netsh`：

- 参数必须严格构造；
- 禁止拼接未经验证的任意用户输入；
- IP / port 必须经过解析；
- 必须检查 exit code；
- 必须记录 stderr；
- 必须避免命令注入。

## 8.3 IP 封停规则命名

不要完全复制原程序：

```text
banIP
```

推荐：

```text
PortGuard-Ban-IP-<normalized-ip>
```

但必须考虑 Windows Firewall rule name 长度与清理问题。

更稳妥的方案：

```text
PortGuard-Ban-IP-<hash>
```

同时在本地数据库保存：

```text
rule_id
ip
created_at
expires_at
permanent
```

### 8.4 不能删除非本程序规则

这是硬性安全要求。

PortGuard 只能删除自己创建的规则。

不得：

```text
按 remoteip=xxx
```

无条件删除系统已有规则。

# 26. 安全原则

这是服务器防护软件，错误比普通桌面软件更危险。

必须：

### 26.1 Fail safe

防火墙操作失败：

- 不假装成功；
- UI 显示错误；
- 日志记录；
- 保留内部状态与实际 Firewall 状态的差异。

```text

blacklist
threshold
restore
```


### 26.3 防止规则泄漏

程序崩溃/异常后：

- 不删除用户已有 Firewall 规则；
- 不误删系统规则；
- 自己创建的规则可被恢复/清理。
