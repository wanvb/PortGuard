# portguard-geo 模块规范

## 职责
- 解析并查询 `ip2region` 的 **xdb v3**（IPv4）二进制数据库，把来源 IP 翻译成可展示的地理文本。
- `db`：文件格式校验、向量索引定位、段索引二分查找、记录读取；文件整体读入内存后只读访问。
- `record`：单条记录的字段解析与展示文案生成（含保留地址判定）。
- `lib`：`GeoLookup` 门面——把「是否启用、文件在哪、能不能用」收敛成一个对象。
- 不做什么：不读配置、不认识抓包与封停、不做缓存、不做网络查询。

## 对外接口
- `UNKNOWN: &str`：`"未知"`，查询不到时的统一展示文案。
- `GeoLookup::load(enabled, candidates: &[PathBuf]) -> GeoLookup`：按顺序尝试候选路径；`enabled = false` 时不做任何文件访问。
- `GeoLookup::ready() -> bool` / `status() -> &str`：库是否可用；状态说明（成功时为文件路径，失败时为中文原因）。
- `GeoLookup::describe(ip: &str) -> String`：生成展示文本；未加载 / 未命中 / IP 非法一律返回 `UNKNOWN`。
- `GeoDb::open(path)` / `from_bytes(Vec<u8>)` / `byte_len()` / `lookup(ip: u32) -> Option<GeoRecord>`。
- `GeoRecord { country, province, city, isp, code }`；`parse(text)` / `is_reserved()` / `describe()`。

## xdb v3 文件布局（实测确认）
```text
[0, 256)              头部
  [0,2)   版本号（必须 = 3）
  [2,4)   索引策略（必须 = 1，向量索引）
  [4,8)   生成时间戳
  [8,12)  段索引区起始（绝对文件偏移）
  [12,16) 段索引区末块起始（= 文件大小 - 14）
  [16,18) IP 版本（必须 = 4）
  [18,20) 指针字节数（必须 = 4）
[256, 524544)         向量索引：256 × 256 项 × 8 字节 = 512 KiB
                      每项 = (端点 A, 端点 B)，绝对文件偏移，半开区间 [lo, hi)
[524544, 段索引起始)   地域信息数据区：UTF-8 文本记录首尾相接，无分隔符
[段索引起始, 文件尾)   段索引：每块 14 字节
                      start_ip(4) | end_ip(4) | data_len(2) | data_ptr(4)
```
查询算法：`row = ip >> 24`、`col = (ip >> 16) & 0xFF` → 向量项位于 `256 + (row*256+col)*8`
→ 在半开区间内按 14 字节步长二分 → 从 `data_ptr` 读 `data_len` 字节 → UTF-8 解析为记录。

> **易错点**：段索引末尾是 `data_len(2)` 在前、`data_ptr(4)` 在后。读反后所有指针都像乱码，
> 且因为绝大多数记录是 ASCII，靠 UTF-8 有效性校验**无法**发现对齐错误，必须核对布局本身。

## 关键约束
- **只用于展示，绝不参与封停判定（规范 22）**：判定路径（白名单 / 黑名单 / 端口 / 阈值）零接触本 crate；
  调用方不得因为查不到地理位置而改变判定顺序或封停行为。
- **不进抓包线程**：查询由控制面板拼装视图时触发，且在运行期锁**之外**执行。
- **不做缓存**：查询是内存字节上的二分查找（微秒级），加缓存只会引入一把多余的锁，违背「简洁实现」约束。
- **失败不静默**：库缺失 / 格式损坏时 `status()` 给出中文原因（含「请放入 <路径>」），而不是悄悄降级；
  但降级本身是允许的——`describe()` 返回「未知」且程序照常运行。
- **解析绝不 panic**：`u16_at` / `u32_at` 一律用 `get()` + `try_into()`；越界、截断、非 UTF-8 均返回 `None` / `Err`。
  非测试代码受 `deny(clippy::unwrap_used, clippy::expect_used)` 约束。
- **库文件不入库、不内嵌**：约 10 MiB 二进制，随程序分发（见 `.gitignore`）；
  查找顺序为 `data/<文件名>` → 程序所在目录 → 当前工作目录，由 `portguard-app` 的 `geo_candidates` 组装。
  本 crate 只接收候选路径列表，不自己决定去哪找。
- **`enabled = false` 不碰磁盘**：关闭展示时连文件是否存在都不检查，避免无谓 I/O。

## 记录与展示
- 原始记录形如 `国家|省份|城市|ISP|国家代码`，例如 `中国|江苏省|南京市|0|CN`。
- `0` 表示占位/无数据，`describe()` 会跳过空字段与 `0`，用 ` · ` 连接剩余字段。
- 国家为 `Reserved` 的段（私有 / 回环 / 保留地址）统一显示「保留地址」，不显示为「未知」。
- 全部字段均为空时显示「未知」。

## 测试
- 位置：内联 `#[cfg(test)] mod tests`（`db.rs` 8、`lib.rs` 5、`record.rs` 5）。
- 关键用例：`命中的地址返回对应记录` / `未命中的地址返回空` / `版本不符被拒绝` / `ipv6数据库被拒绝` /
  `记录指针越界只返回空不恐慌`、`展示文本跳过占位零` / `保留地址段显示为保留地址`、
  `关闭时不做文件访问且恒为未知` / `找不到文件时状态指明应放位置` / `候选路径中命中第一个存在的文件`、
  `真实数据库可加载并命中已知地址` 与 `真实数据库可查询常见地址`（仓库根目录无 `ip2region_v4.xdb` 时自动跳过）。
- 合成库：`db.rs` 测试用 `build_db()` 拼一个最小可用的 xdb，不依赖外部文件。

## 依赖关系
- 依赖：`portguard-core`（仅用于统一错误类型与 crate 约定）。
- 被依赖：`portguard-app`（`Controller` 持有 `RwLock<GeoLookup>`，保存配置时重载）。
